# Memory Map 要件定義

## 1. 概要

Memory Mapは、カップルや友人が共有する思い出と行ってみたい場所を地図上で管理するスマートフォン優先のPWAです。

- 地図表示：Leaflet、OpenStreetMap
- ホスティング：GitHub Pages
- 認証：Firebase Authentication（Googleログイン）
- 場所検索：Google Places APIを経由するFirebase Functions
- ピン保存：当面はブラウザのlocalStorage、将来はFirebase Firestoreへ移行
- 対象：スマートフォン、PC

## 2. 目的

- 行った場所に写真やメモなどの思い出を残す
- これから行きたい場所をふたりの地図に追加する
- ホストが承認したメンバーだけが閲覧・編集できる共有マップを提供する
- LINE、Safariなどのブラウザから使いやすい操作を提供する

## 3. ユーザー・権限

### 3.1 ユーザー

- ホスト（マップ作成者）
- 招待された共同編集者
- 閲覧者（将来検討）
- 未ログインユーザー

### 3.2 権限

- 未ログインユーザーは地図を閲覧できない
- ホストは招待、共同編集者の削除、ピンの追加・編集・削除ができる
- 招待された共同編集者はピンの追加・編集・削除ができる
- 招待していない第三者は閲覧・編集できない

## 4. 認証

### 4.1 対応要件

- Googleアカウントでログインできる
- PCとスマートフォンの通常ブラウザで安定してログインできる
- LINE内ブラウザではFirebase認証を開始せず、外部ブラウザへ移行する案内を表示する
- LINE内ブラウザの案内では「ブラウザで開く」と「ログインURLをコピー」を縦に表示する

### 4.2 外部ブラウザ案内

Googleアカウントでログインする必要がある旨を説明し、ユーザーがブラウザへ移動できる手段を提示する。LINE内ブラウザから外部ブラウザへ強制遷移する標準APIは存在しないため、確実な遷移はユーザー操作を伴う。

## 5. 地図・ピン

### 5.1 地図

- Leafletで地図を表示する
- 地図操作はスマートフォンで使いやすくする
- 地図上に「思い出」「行ってみたい」のピンを表示する
- ピンを選択すると詳細情報を表示する

### 5.2 ピン追加

- 地図上の任意の場所をタップして追加できる
- 住所や店名を検索して候補を選び追加できる
- 候補から緯度・経度を取得して地図へ表示する

### 5.3 ピン種別

各ピンには種別を設定する。

- 思い出
- 行ってみたい

### 5.4 ピン情報

- 場所名
- 住所
- 緯度・経度
- Place ID（内部保持）
- カテゴリ
- ピン色
- ピンアイコン
- メモ
- 写真・動画リンク
- 登録日時
- 更新日時

### 5.5 ピン編集・削除

- ピン詳細から削除できる
- 将来、編集画面からメモ・種別・色・アイコン・写真・動画を変更できる

## 6. メニュー

### 6.1 サイドメニュー

画面左上の三本線アイコンから左側にスライドインするメニューを表示する。メニューアイコンは背景を持たない単純な三本線とする。

メニュー項目：

- 思い出リスト
- 行ってみたいリスト
- ログアウト

### 6.2 ピンリスト

- メニューからピン種別ごとの一覧を表示する
- リスト項目を選択すると地図上の該当ピンへ移動する
- リストは登録済みピンと同期する

## 7. 保存・共有

### 7.1 現在の保存方式

- ピン情報はブラウザのlocalStorageに保存する
- ページ更新時と再ログイン時に、同じブラウザ内では保存済みピンを復元する
- 端末・ブラウザをまたぐ同期には対応しない

### 7.2 将来の保存方式

- Firebase Firestoreへ移行する
- ユーザーごとのマップ所属情報を保存する
- ホストが招待したユーザーのみアクセスできるルールを設定する
- 複数端末・共同編集者間でリアルタイム同期する

## 8. 写真・動画・メモ

### 8.1 メモ

- ピンごとに文章メモを保存できる

### 8.2 写真

- 写真を複数追加できる
- 当面は外部URLまたはGoogle Driveリンクを利用する
- 将来的にFirebase StorageまたはGoogle Drive連携へ移行する

### 8.3 動画

- 動画ファイル自体ではなく、Google Drive等の共有URLを保存する
- Firestoreに保存するURLへのアクセス権は、閲覧対象ユーザーと一致させる

## 9. UI要件

### 9.1 デザイン方針

- スマートフォン操作を優先する
- 地図を主役として表示する
- 白を基調にし、タイトル・メニュー・検索欄を地図より上に配置する
- ブラウザ標準の余白やスクロールを避け、ヘッダーと地図を画面内に収める

### 9.2 ヘッダー階層

スマートフォンでは、上から次の順に表示する。

1. タイトルとメニュー
2. ピン検索欄
3. キャラクター
4. 地図

キャラクターは透明背景の人物画像を使用し、タイトルの一部に重なることを許容する。キャラクターでタイトルが読みにくくならない位置に配置する。

### 9.3 タイトル

- 表示名：Memory Map
- 筆記体に近いフォントを使用する
- サブタイトル：「おじいちゃん おばあちゃんになっても続く」
- サブタイトルはタイトルより小さい筆記体を使用する

### 9.4 ピン検索

- 入力欄と検索ボタンを横並びにする
- ボタン名：「ピン検索」
- ボタン色：青
- 入力欄の高さはスマートフォン画面で操作しやすい最小限の高さにする
- 検索候補表示中は候補を検索欄直下に重ねて表示する

### 9.5 キャラクター

- 添付されたキャラクター画像を縮小表示する
- キャラクター画像は人物部分を切り抜き、黒背景のみ透過する
- まつ毛や髪、衣服など人物の濃色部分を消さない

### 9.6 レスポンシブ対応

- 幅640px以下をスマートフォン表示とする
- 幅641px以上はPC・タブレット表示とする
- 横幅が狭い場合でもタイトル、検索欄、キャラクターが重なり過ぎない

## 10. PWA要件

- ホーム画面に追加できる
- スタンドアロン表示できる
- Web App Manifestを提供する
- アプリ名をMemory Mapとして表示する
- アイコンにキャラクター画像を使用する

## 11. 非機能要件

### 11.1 セキュリティ

- APIキーをブラウザ公開前提で適切に制限する
- Places APIキーはサーバー側Secretとして管理する
- Firestore Security Rulesで未承認ユーザーのアクセスを拒否する
- 動画URL等に機密情報を含めない

### 11.2 性能

- 初期表示を高速に保つ
- 検索候補は必要に応じてキャッシュする
- 大量ピン時も地図操作と一覧表示を遅くし過ぎない

### 11.3 可用性

- GitHub Pagesの無料枠を利用する
- Firebase無料枠の利用量を定期的に確認する
- OSM、Google Places、Firebaseの障害時はエラーを表示する

## 12. 受け入れ基準

- PC・スマートフォンでMemory Mapが表示される
- スマートフォンでメニューが左側からスライド表示される
- メニューアイコンに不要な背景がない
- タイトル、検索欄、キャラクター、地図が指定階層で表示される
- 「ピン検索」で場所を検索して候補を選択できる
- 選択した場所にピンが追加される
- ピンを削除できる
- ページ更新後も同じブラウザ内でピンが保持される
- ログアウト後にログイン画面へ戻る
- LINE内ブラウザではGoogleログインを直接開始せず外部ブラウザ案内を表示する

## 13. 将来機能

優先度順に検討する。

1. ピン種別選択（思い出／行ってみたい）
2. ピンごとの写真・メモ・動画リンク
3. ピン色・アイコン変更
4. Firestoreによる複数端末・共同編集同期
5. 招待リンクとホスト承認
6. 共有マップの閲覧権限管理
7. オフライン対応の強化

## 14. 現在未実装

- 思い出・行ってみたいのピン分類切り替え
- 写真・動画・本文メモの保存
- ピン色・11色以上の色選択
- 施設種別に応じたピン形状・絵文字アイコン
- Firestore共有
- 招待・承認フロー
- アクセス権限ルール

## 15. 技術構成

### 15.1 使用技術

- フロントエンド：HTML、CSS、JavaScript
- 地図ライブラリ：Leaflet
- 地図タイル：OpenStreetMap
- 場所検索：Google Places API（New）のText Search
- 認証：Firebase Authentication、Googleログイン
- サーバー処理：Firebase Functions v2
- PWA：Web App Manifest、Service Worker
- バージョン管理・公開：GitHub、GitHub Pages

スマートフォンのホーム画面追加にも対応する。地図や認証以外のUIはブラウザ上の静的ファイルとして提供する。

### 15.2 公開先

- GitHubリポジトリ：`Riki-130/memory-map`
- 公開URL：`https://riki-130.github.io/memory-map/`
- ホスティング方式：GitHub Pages

### 15.3 Firebase構成

- FirebaseプロジェクトID：`memory-map-rh130-2026103-eff07`
- Firebase Functionsランタイム：Node.js 22
- Cloud Function：`searchPlaces`
- Cloud Functionリージョン：`asia-northeast1`
- Function用エンドポイント：`asia-northeast1-memory-map-rh130-2026103-eff07.cloudfunctions.net/searchPlaces`
- Firebase Functions Secret：`PLACES_API_KEY`

ブラウザ向けFirebase設定とPlaces APIキーは用途別に分離する。Places APIキーはSecretとしてサーバー側で管理し、HTMLやJavaScriptへ値を書かない。

### 15.4 ファイル構成

- `index.html`：画面構造、認証パネル、ヘッダー、メニュー、地図領域
- `styles.css`：レスポンシブレイアウト、スマートフォン優先のUI、配色、メニュー
- `app.js`：地図、ピン追加・削除、localStorage保存、場所検索候補、ピン一覧
- `firebase-auth.js`：Firebase初期化、Googleログイン、ログアウト、LINE内ブラウザ案内
- `firebase-config.js`：ブラウザ向けFirebase設定
- `search-config.js`：`searchPlaces` Functionsエンドポイント設定
- `manifest.json`：PWA設定
- `service-worker.js`：PWAキャッシュ設定
- `firebase.json`：Firebase Functionsソース設定
- `.firebaserc`：Firebaseデフォルトプロジェクト設定
- `assets/`：キャラクター画像など静的画像
- `functions/index.js`：Google Places APIを呼び出す`searchPlaces` Function
- `docs/requirements.md`：要件・設計・改善履歴

### 15.5 外部API・サービス

- GitHub Pagesの静的配信
- OpenStreetMapの地図タイル
- Google Places API
- Firebase Authentication
- Firebase Functions
- 将来利用予定：Firestore、Firebase Storageまたは外部動画共有URL
